# Lucid — Security Architecture & Production Reliability

This document outlines the security controls, authentication mechanisms, network hardening, rate limiting, and failure containment architectures protecting the Lucid platform.

---

## 1. Authentication & Session Security

Implemented across `backend/auth/` and `backend/api/v1/auth.py`:

### 1.1 Password Hashing & Key Derivation
- Passwords are never stored in plaintext. Lucid utilizes **Argon2id** via `argon2-cffi` (`backend/api/v1/auth.py`) configured with institutional parameters:
  - Memory cost: $m = 65,536 \text{ KiB}$ (64 MiB)
  - Time cost: $t = 3 \text{ iterations}$
  - Parallelism: $p = 4 \text{ lanes}$
  - Salt: Cryptographically random 16-byte salt per password
- Memory-hard defense resistant against specialized GPU, ASIC, and FPGA brute-force cracking attacks.
- Backward compatibility: Seamlessly verifies legacy bcrypt hashes (`$2b$`) and transparently re-hashes them on password updates.

### 1.2 JWT Token Lifecycle & Instant Session Invalidation
- **Access Tokens**: Short-lived (60 minutes) JSON Web Tokens signed using HMAC-SHA256 (`HS256`).
- **Refresh Tokens**: Cryptographically random UUID tokens stored securely to enable seamless session renewal without re-entering credentials.
- **Revoked Token Blacklist (`revoked_tokens` table)**: Upon user logout or security breach detection, token JTIs (JWT IDs) are persisted in PostgreSQL. Incoming requests with blacklisted tokens are immediately rejected with HTTP 401 Unauthorized.

### 1.3 Role-Based Access Control (RBAC)
- Strongly enforced user roles:
  - `investor`: Standard retail permissions (view own portfolios, run diagnosis, generate recommendations).
  - `advisor`: Professional permissions (review client allocations, audit suitability).
  - `admin`: Operational permissions (trigger full exchange synchronizations, inspect system telemetry).

## 2. HTTP Security Hardening & Gateway Protection

Implemented in `backend/main.py` via custom Starlette and FastAPI middleware:

### 2.1 Enterprise HTTP Security Headers
Every HTTP response generated by FastAPI is enriched with defensive headers:
- `X-Content-Type-Options: nosniff`: Prevents MIME-type sniffing.
- `X-Frame-Options: DENY`: Defends against clickjacking in iframes.
- `X-XSS-Protection: 1; mode=block`: Activates browser cross-site scripting filters.
- `Referrer-Policy: strict-origin-when-cross-origin`: Restricts referrer leakage.
- `Permissions-Policy: geolocation=(), camera=(), microphone=()`: Blocks hardware API access.
- `Strict-Transport-Security: max-age=31536000; includeSubDomains`: Mandates HTTPS in staging and production environments.

### 2.2 Strict CORS Policy
Restricts cross-origin browser requests strictly to authorized frontend origins (e.g., `http://localhost:3000`). Wildcard `*` origins are prohibited.

## 3. Rate Limiting & Denial-of-Service Defense

Implemented via `InMemoryRateLimiterMiddleware` (`backend/middleware/rate_limit.py`):
- **Sliding-Window In-Memory Tracking**: Tracks IP addresses and API keys with millisecond accuracy.
- **Tiered Endpoint Protection**:
  - `Authentication Endpoints` (`/api/v1/auth/login`, `/register`): Capped at 10 requests per minute to prevent credential stuffing.
  - `Agentic AI Generation` (`/api/v1/portfolios/generate`): Capped at 5 requests per minute to prevent compute exhaustion and protect LLM token quotas.
  - `Standard Market Data Endpoints`: Capped at 60 requests per minute.
- Returns standard HTTP 429 Too Many Requests with `Retry-After` headers when limits are exceeded.

## 4. Failsafe Architecture & Circuit Breakers

### 4.1 Production Security Key Validation (Fails Closed)
Implemented in `backend/config.py`:
```python
def validate_security_keys(self) -> None:
    if self.app_env.lower() in ("staging", "production"):
        if not self.jwt_secret_key or "change-me" in self.jwt_secret_key or len(self.jwt_secret_key) < 32:
            raise ValueError(
                f"CRITICAL SECURITY CONFIGURATION ERROR: Environment '{self.app_env}' strictly requires "
                f"a non-default JWT_SECRET_KEY of at least 32 characters (RFC 7518 Section 3.2)."
            )
        if not self.app_secret_key or "change-me" in self.app_secret_key:
            raise ValueError(
                f"CRITICAL SECURITY CONFIGURATION ERROR: Environment '{self.app_env}' strictly requires "
                f"a non-default APP_SECRET_KEY."
            )
```
The application intentionally halts at startup if default, insecure, or truncated keys are configured in production.

### 4.2 External API Resilience
- **BSE Anti-Bot Defense**: When `api.bseindia.com` blocks automated headless requests with HTTP 403 Forbidden (Cloudflare Turnstile), Lucid never attempts to bypass or hack the gate. Instead, it seamlessly resolves BSE equity listings via SEBI-mandated universal ISIN matching and local verified registries.
- **Yahoo Finance Fallback**: Caches historical price data in PostgreSQL `market_prices`. If external endpoints throttle or experience network failure, the platform operates transparently on latest cached closing prices.
- **RBI Macroeconomic Fallback**: Built-in institutional baseline defaults (Repo Rate: 6.50%, CPI: 5.1%) ensure that monetary policy analysis never stalls during central bank portal updates.

### 4.3 Non-Custodial Advisory Boundary
- Lucid is strictly an **intelligent advisory platform**, not an automated execution bot.
- All broker orders (BUY/SELL) generated during initial allocation or rebalancing require explicit, discretionary investor approval in the UI before transmission. Lucid never triggers automated broker executions without user consent.
